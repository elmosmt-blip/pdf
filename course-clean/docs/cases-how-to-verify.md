# Как проверить четыре кейса — пошагово

Короткая инструкция для проверки человеком. Ничего не устанавливается, всё уже
работает в текущей сборке.

---

## 0. Что открыть

Препятствие номер один, и оно неочевидное: **курс — это hash-роутер**. Адрес
страницы после решётки (`#/…`) браузер на сервер не отправляет, поэтому ссылку
вида `/course-clean/#/c/cx-m03-01` открыть нельзя — сервер вернёт 404. Открывать
нужно **корень**, а кейс выбирать внутри страницы.

| Что | Как |
|---|---|
| Курс | живое превью в панели (порт 8080) или `index.html` двойным кликом |
| Все кейсы | главная → карточка модуля **02 / 03 / 06 / 14** → блок **Toolkit** |
| Один кейс | меню слева: раскрыть модуль → **Toolkit (1 case)** |

Готовые адреса для навигации внутри уже открытой страницы:

```
#/c/cx-m03-01   трафарет: 0.4 мм QFP-48 не отдаёт пасту   (m03, 8 шагов)
#/c/cx-m02-01   влага: катушка в шкафу 7 % RH              (m02, 6 шагов)
#/c/cx-m06-01   профиль оплавления: пик 248 °C             (m06, 7 шагов)
#/c/cx-m14-01   AOI: DPMO, выборка ISO 2859-1, 8D          (m14, 10 шагов)
```

Их можно вставить в адресную строку **после** того, как курс уже открыт, — или
просто кликать по Toolkit.

## 1. Пройти кейс как учащийся (5 минут на один)

1. Откройте `cx-m03-01`. Проверьте, что на странице есть: чип **Board X**,
   время, число шагов, `rubric 100 pts`, сценарий, свёрнутый блок **Board X —
   the product behind this case**, файл данных `aperture-table.csv`
   (раскрывается, внутри кнопка Download).
2. Нажмите **Check my answers**, ничего не заполнив. Ожидаемо: под каждым
   полем появляется красная строка («Enter a number before checking…»), шаг
   обводится, курсор прыгает в первое поле, **оценки нет**.
3. Введите ответ, потом нажмите **Show a hint** — число в поле должно
   остаться. Это специально проверяется тестом: ответы хранятся в состоянии
   движка, а не читаются из DOM.
4. Введите `0,64` (запятая) в шаг 1 — принимается наравне с `0.64`.
5. Заполните всё правильно (ключи — в таблице ниже) → **Check my answers**.
   Ожидаемо: `100 % — 100 of 100 rubric points`, «Mastered. The rubric
   threshold is 80 %», таблица начислений по критериям, кнопки
   **Try again from a clean sheet** и **Download my answers (CSV)**.
6. Скачайте CSV — в нём по строке на шаг: ваш ответ, вердикт, правильное
   значение, единица, допуск, и итог.
7. Вернитесь в модуль (крошка сверху) — в блоке Toolkit у кейса теперь
   «best 100 %».

## 3. Проверка «снаружи» — без браузера

Всё, что видит учащийся, можно проверить командами. Это же и есть защита от
подмены: ключи не набраны руками, их пересчитывает второй, независимый скрипт.

```bash
cd /home/user/pdf/course-clean

# 1) данные совпадают с генератором (ничего не правили руками)
python3 scripts/gen_cases.py --check

# 2) все 31 ключ пересчитаны независимо + контрольные числа брифа
node scripts/check-cases.js

# 3) целостность курса и embed = JSON
node scripts/check-integrity.js

# 4) весь набор тестов, включая рендер кейсов в jsdom
node tests/course.test.js
```

Что должно быть в выводе:

| Команда | Ожидаемый результат |
|---|---|
| `gen_cases.py --check` | `OK (12 cases, 107 steps)` |
| `check-cases.js` | `keys recomputed 107 of 107`, восемь строк `ok` с контрольными числами, `OK — …every key reproduces independently` |
| `check-integrity.js` | `cases 12 (107 steps)`, `OK — integrity check passed` |
| `tests/course.test.js` | `PASS — 189 passed, 0 failed` |
| `tests/case-qa.js` | `48 passed, 0 failed/errored` |

Ключи с формулами лежат в `docs/case-keys.csv` — его можно открыть в Excel и
пересчитать любую строку вручную.

## 4. Что проверить глазами как технолог

Числа сходятся автоматически; смысл — только глазами. Стоит посмотреть:

1. **m03, s8** — согласны ли вы, что ступенька 0.100 мм только над QFP-48
   лучше, чем уменьшать весь трафарет. Это редакционное решение, а не расчёт.
2. **m02, s4** — формулировка «5 % RH — требование, 10 % — замедление» это то,
   что мы исправили в Фазе 2. Проверьте, что она совпадает с вашей процедурой.
3. **m06, s3/s5** — что для вашего BGA класс корпуса действительно «крупный»,
   то есть предел 250 °C, а не 245 °C. Это единственное место, где кейс мог бы
   разойтись с реальным чертежом.
4. **m14, s5** — приемлемо ли для вас, что при Ac = 3 партия принимается, а 8D
   остаётся открытым.
5. **Пороги 0.66 / 1.5 / 75 % / 2–5 с** — взяты из уроков и источников, но не
   из текста стандартов: если у вас есть текст редакции, это первое, что стоит
   сверить (см. `docs/edition-registry.csv`, колонка «Recheck required»).

## 5. Ограничение, которое честно стоит знать

Скриншотов в PNG нет: в песочнице нет браузера (CDN Playwright, зеркало Debian
и Chrome-for-Testing недоступны, root для apt нет). Вместо них лежат
`docs/screenshots/cx-*.outline.txt` — это реальный DOM, снятый с работающего
движка, а не макет.

На машине с браузером картинки снимаются одной командой:

```bash
node scripts/capture-case.js --all --png
```

Без браузера команда завершается с кодом 2 и сообщением «no browser binary
found» — не подсовывает картинку, которой не было.
