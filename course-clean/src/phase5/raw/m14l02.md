## Separate the failure, the causes and the escape
Cause analysis starts by separating three questions: what physical failure occurred, what process conditions made it likely, and why the defect was not detected.

A root cause is the condition that, once corrected, prevents recurrence under the same operating assumptions. Contributing causes raise probability or severity without being sufficient alone. A detection escape is a gap in inspection, test or sampling.

Most bad investigations collapse these three into one sentence, and then fix the detection while the cause stays in the process.

## Why-chain for narrow failure modes
The why-chain, the 5-Why, suits a narrow failure mode with a mostly linear sequence.

Ask why until the answer points at a controllable process parameter, a design condition or a management-system gap, then stop and verify with evidence. Tombstoning can run from uneven wetting to asymmetric paste deposit, to stencil alignment or paste rheology, to setup verification.

Avoid stopping at operator error, which is usually a description of the process rather than a cause.

## Fishbone for interacting cause families
A fishbone works better when many cause families may interact.

Use categories such as machine, method, material, measurement, environment and management, and populate them with testable hypotheses: reflow profile drift, paste viscosity or metal content, stencil aperture wear, placement nozzle force, feeder misalignment, wave conveyor speed, flux activity, humidity and inspection coverage.

The diagram organises the investigation; it does not prove anything until each branch is tested.

## Fault tree for combined causes and escapes
Fault tree analysis helps when the top event can result from several independent or combined causes.

Define the top event narrowly, such as an open joint or a tombstoned component, then decompose it with AND and OR gates. An open joint may need both insufficient wetting and mechanical disturbance, while a tombstone may follow from severe paste asymmetry or severe placement offset.

Fault trees make detection escapes explicit, because the tree shows the branch that should have caught the defect and did not.

## Change-point analysis
Change-point analysis compares behaviour before and after a suspected change.

Common changes are paste lot, stencil, reflow profile, placement nozzle, feeder setup, wave chain speed, flux lot or AOI program revision. Use a before and after defect rate, a control chart, or a change-point statistic where data allow.

Confirm that the change occurred before the shift, that it affected the product and process in question, and that nothing else moved at the same time.

## Report the three categories separately
Separate root cause, contributing causes and detection escape in the final report.

The root cause is the item for corrective action, such as an unqualified paste lot property or a stencil aperture outside the qualified range. Contributing causes may be a marginal reflow profile, a worn nozzle or high placement speed, and they can be reduced by risk controls even when they are not primary.

The detection escape is closed by inspection or test changes, such as AOI program limits, X-ray sampling, functional test coverage or the IPC-A-610 visual acceptability criteria, and it needs its own owner.

## Close with verification and updated controls
Close with verification.

Containment protects the customer, corrective action removes the root cause, and effectiveness checks confirm that the defect rate, escape rate or process parameter has returned to an acceptable state. Update the control plan, the FMEA, the work instructions and the inspection program.

Use SI units for temperatures, times, distances and volumes, and state the uncertainty or the sampling limits behind the numbers. Avoid absolute language: standards and contracts allow exceptions, so record the applicable IPC-A-610 class and the IPC/JEDEC J-STD-001 requirements alongside any approved deviation.

## Key takeaways
Name the failure, the cause and the escape separately, because fixing detection on an unproven cause hides the defect rather than removing it.
Stop the why-chain at a controllable parameter, since operator error describes the process without changing it.
Verify effectiveness against a rate, because a corrective action without a measured before and after is a claim.

## Common mistakes
Closing a case at operator error :: Trace to the process condition that allowed it, because the same error recurs with a new operator.
Treating a contributing cause as the root cause :: Keep the categories apart, since the risk control differs from the corrective action.
Fixing detection first because it is faster :: Address the escape and the cause with separate actions, because a better inspection finds more of the same defect.

## Glossary
Root cause :: The condition whose correction prevents recurrence under the same assumptions.
Detection escape :: A defect that passed the inspection or test intended to catch it.
Fault tree :: A top-down logic diagram using AND and OR gates to decompose a failure event.
Change point :: A point in time at which a process measurement shifts, often following a deliberate change.
