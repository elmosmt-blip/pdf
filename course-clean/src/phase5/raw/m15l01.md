## Make feedback actionable
Designers act on feedback written as a constraint, not a complaint.

A useful process note names the affected component or layer, the observed failure mode, the measurable process variable and the proposed design rule. "Small chip passives tombstone on the right side of the panel when paste apertures are asymmetric" is actionable; "the board is bad" is not.

The request should be short enough to read quickly and specific enough that a designer can change a rule file, a land pattern or a stencil without asking for clarification.

## Translate process language into design variables
Use language that maps a process observation onto a design variable.

Instead of "the solder is not wetting well", name what controls wetting: pad finish, copper area, paste aperture area, stencil thickness, reflow ramp, component mass.

On SMT the designer can change land-pattern geometry, paste apertures, copper balance and thermal relief. On through-hole work they can change hole size, annular ring, solder mask clearance and component selection. The designer cannot change "wetting"; they can change those variables.

## The format designers can approve
The format that gets action is an ECN or DCR with a clear decision point.

Start with the problem statement, then evidence, affected part numbers, proposed change, test plan, cost, schedule and risk. Name the exact layer or file: paste stencil layer, solder mask layer, copper layer, component library, assembly drawing.

Where the change touches acceptance, land pattern, board fabrication or BGA design, name the relevant IPC standard and the clause it applies.

## Make the change bounded and testable
Designers prioritise changes that reduce a measured risk, fit the existing board and can be verified without a full requalification.

"Make the pads bigger" invites rejection, because it can affect routing, impedance, assembly density or solder mask bridges. "Increase the paste aperture area on the low-volume side by 8 % to 12 % and verify SPI paste volume inside the process window" gives a bounded change and a test that proves it.

The difference between the two requests is the difference between a wish and a proposal.

## Convert a limitation into a design rule
To turn a process limitation into a design rule, identify the physical cause, express it as a design variable, and set a measurable limit.

For tombstoning the causes are unequal paste volume, unequal pad copper area, asymmetric thermal mass and placement offset. A testable rule reads: for small chip passives, the paste apertures on both ends shall have areas within ±10 % of each other, the copper pads shall be symmetric, and the placement centre shall be within ±0.05 mm of the pad centre.

Each clause is measurable, which is what makes it a rule rather than an intention.

## Apply the same logic to THT
On wave soldering, insufficient fill and solder balls follow from hole-to-lead clearance, pad size and flux activity.

A design rule can specify a clearance range, an annular ring and the solder mask web between pads. Because hole plating, drill wear and the wave profile vary, state the range and verify it against the board fabricator and the assembly equipment.

Ask the fabricator for the expected drilled hole tolerance and plated hole size, then set the rule from the achievable process rather than from a nominal drawing value.

## Defending the ECN or DCR
Expect objections: the board worked before, the change costs money, the supplier cannot support it, test coverage is incomplete, the change touches another product.

Answer with data and a bounded plan: defect rate before and after, affected part numbers, test sample, fallback if the change fails, and the parts or files that will not change.

Where the change is too large for one step, propose a pilot panel or a product with high volume enough to prove it first.

## Close with a rule and a proof
A good process feedback note ends with what the designer must change and what the process team will prove.

Example: "Change the small chip passive paste apertures to symmetric rectangles with equal area; process will verify SPI paste volume, AOI tombstone rate and reflow profile on 300 boards before release."

That gives the designer a rule change and the process team a testable commitment, and neither is asked to do the other's job.

## Key takeaways
Name the design variable rather than the symptom, because a designer can only change a layer, a dimension or a rule.
Bound the request with a number and a test, since an unbounded change asks for trust instead of evidence.
Offer the proof with the request, because a designer approves a change they can see verified.

## Common mistakes
Sending a defect report with no design variable in it :: Convert the symptom to a variable, because nothing on the drawing changes otherwise.
Asking for a rule with no measurable limit :: Set the limit in percent or millimetres, since a rule that cannot be measured cannot be audited.
Raising the same request every quarter :: Close it with a rule and a verification, because an open request loses credibility.

## Glossary
ECN :: Engineering change notice, the formal record that authorises a design change.
Design variable :: A drawing, layer, dimension or library attribute the designer controls.
Design rule :: A measurable constraint applied during layout or stencil design.
Pilot panel :: A limited build used to prove a change before full release.
