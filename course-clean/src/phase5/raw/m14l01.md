## Start with measured defect data, not with opinions
A defect problem becomes manageable once measured data describes it, before any analysis starts.

The first task is not to decide whether the printer, the placer, the oven, the wave or the operator is at fault. The first task is to define what was measured, where, in what unit, and against which acceptance rule.

"The oven is causing tombstoning" is an opinion until stage-specific counts, component references, board identifiers, lot data, process parameters and inspection results support it. "Reflow-stage confirmed defects are the largest contributor this week" is a measured observation, provided the taxonomy and the inspection integrity are known.

Treat defect data as a measurement system: if the measurement system is weak, every conclusion built on it is weak too.

## Build a defect taxonomy
A useful defect taxonomy records the defect mode, the assembly stage, the inspection or test point, the product, the board or lot identifier, the line, the shift, the equipment, the recipe and the disposition.

The defect mode says what was found: insufficient solder, excess solder, misalignment, tombstoning, bridging, voiding, lifted lead, solder ball, component damage or contamination. The stage says where it was detected and, where known, where it was created.

A taxonomy only pays off when the fields are filled the same way every shift, which is a discipline problem before it is a database problem.

## IPC acceptance and rework standards as the defect language
For visual and workmanship decisions, IPC-A-610 gives the acceptance criteria and IPC-7711/7721 gives the rework and repair guidance.

These standards matter because they supply a common language for classification and disposition. Acceptance still depends on product class, customer requirements and the specific defect condition.

Do not assume every visible anomaly is a reject, and do not assume every reject is a confirmed process defect.

## Pareto by stage
A Pareto by stage answers which stage contributes the largest share of confirmed defects, escapes, rework, scrap or test failures.

A final-test Pareto alone hides upstream causes: a functional failure can come from a reflow defect, a placement defect, a through-hole insertion problem or a test setup issue.

A stage-based Pareto separates incoming material, paste print, placement, reflow, through-hole insertion, wave solder, in-circuit test and functional test, so the contribution is visible where it was made.

## Measurement integrity determines whether the Pareto is trustworthy
Measurement integrity asks whether the inspection or test system detects the defect it is meant to detect and whether it avoids false calls.

On SMT the measurement systems are SPI for paste volume and area, AOI for component and solder condition, X-ray for hidden joints, in-circuit test for connectivity, functional test for operation and manual visual inspection. On through-hole work they are insertion verification, wave inspection and the same electrical tests.

An unaudited measurement system produces a Pareto of its own biases.

## Record process parameters in SI units and trace them to the defect
Defect data becomes actionable when it is linked to process parameters in consistent SI units.

Print data may include stencil thickness in mm, aperture dimensions in mm, paste volume in mm³, squeegee pressure in Pa or N depending on the printer interface, print speed in mm/s and paste temperature in °C. Placement data may include nozzle force in N, placement speed in mm/s, component offset in mm and feeder pickup accuracy in mm. Reflow data may include zone temperatures in °C, conveyor speed in mm/s and atmosphere in ppm oxygen.

Trace each parameter to the defect it is suspected of causing, or the correlation stays a story. Verify the actual ranges against your paste datasheet, stencil design, printer datasheet, oven profile, wave or selective solder machine datasheet, and IPC-7525, IPC-7526, IPC-7530 or IPC-7711/7721 guidance where applicable.

## Define the denominator before comparing stages
A defect count without a denominator misleads.

The denominator may be boards produced, boards inspected, components placed, joints inspected, test cycles or units shipped, and a stage defect rate must state which. Defects per board, per thousand boards, per million joints and failures per test cycle are different metrics.

Where one stage inspects every board and another samples a subset, raw counts cannot be compared directly.

## Use the Pareto to select the next measurement, not to assign blame
The output of a stage-based Pareto is a short list of stages and defect modes that justify further measurement.

If reflow-stage confirmed defects dominate, stratify by component type, package size, board location, paste lot, stencil design, oven profile or AOI program. If paste print defects dominate, review SPI data, stencil condition, squeegee settings, paste rheology and registration. If through-hole or wave defects dominate, review insertion, hole fill and wave parameters.

Assigning blame is not an output; choosing the next measurement is.

## Key takeaways
Separate calls from confirmed defects before plotting, because a false-call rate becomes a Pareto bar if nobody audits it.
Keep the denominator with every rate, since stage comparisons collapse when one stage samples and another inspects everything.
Let the Pareto choose the next stratification, because a chart that ends in a person produces no measurement.

## Common mistakes
Ranking stages by raw inspection calls :: Rank by confirmed defects, because inspection bias is not process performance.
Auditing the defect database once and assuming it is stable :: Re-audit after program or product changes, since the bias returns with them.
Comparing a sampled stage with a fully inspected stage :: Normalise the denominator, because sampling changes the count and not the process.

## Glossary
Pareto :: A ranked bar chart of defect counts or rates by category, used to choose where to work first.
False call :: An inspection or test failure reported on an assembly that is actually acceptable.
Measurement integrity :: The ability of an inspection system to detect defects without inventing them.
Stratification :: Splitting a defect population by a second variable to find where the effect concentrates.
