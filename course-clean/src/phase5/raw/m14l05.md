## Corrective and preventive action
Corrective action responds to a detected nonconformity, such as a solder defect found by AOI, X-ray, functional test or a customer complaint.

Preventive action addresses a credible potential failure before it happens: a stencil aperture close to a paste-release limit, or a wave pot temperature drifting towards its control limit.

In an 8D, containment protects the customer before the root cause is known, corrective action removes the cause, and preventive action keeps the next product out of the same hole.

## 8D content an auditor can trace
A usable 8D records the problem statement, affected part numbers and lots, containment quantity and disposition, team roles, root cause, corrective action, implementation evidence, effectiveness metric and closure decision.

Name owners by role: SMT process engineer, line supervisor, quality engineer, PFMEA owner. Use actual dates from the CAPA or 8D record, not assumed ones, and keep the evidence attached rather than summarised.

An auditor follows the chain from the complaint to the changed control, so every link needs a document.

## Containment that is proportionate
Containment can be quarantine of suspect lots, full inspection, rework, a temporary parameter lock, or a hold on shipping.

Match the method to the risk: a safety-related joint defect may need full inspection and customer notification, while a cosmetic issue may need sampling and disposition by a documented plan.

Verify containment by checking the inspected population against the population you believed you had. A containment claim with no count behind it is a statement of intent.

## Occurrence, detection and systemic cause
For SMT and through-hole defects, separate the cause that created the defect from the cause that let it escape.

Occurrence causes include paste volume, stencil aperture design, reflow profile, wave solder temperature, flux activity, component coplanarity, feeder calibration and handling damage. Detection causes include AOI program coverage, X-ray sampling, test coverage and operator judgement. Systemic causes include missing controls, unclear work instructions and absent verification.

All three belong in the report, because each needs a different action.

## Choosing a corrective action that survives production
Select the action that addresses the verified root cause and can be sustained.

Examples: changing a stencil aperture, adding a poka-yoke fixture, revising a reflow profile, replacing a worn feeder, changing a supplier lot, or adding a sensor check.

A parameter adjustment is valid where the root cause is drift or misconfiguration, provided the data and the equipment datasheet support the setting, and provided the correction cannot be quietly reversed on the next shift.

## Effectiveness verification before closing
Define the effectiveness metric before implementation.

Common metrics are defect rate in ppm, first pass yield, AOI escape rate, X-ray void percentage, wetting quality and functional test failure rate. Verification needs enough production time and sample size to detect recurrence, and the acceptance criterion should be agreed with quality and, where required, the customer.

If the metric misses the target, the 8D stays open.

## Example closure record
A practical closure record reads like this: containment dated 2026-01-15 with the line supervisor as owner; corrective action implemented 2026-01-22 with the SMT process engineer as owner; effectiveness verified 2026-02-05 with the quality engineer as owner; the effectiveness metric is defect rate in ppm against a target of 500 ppm; the PFMEA and control plan update belongs to the PFMEA owner.

Dates, owners and metric are copied from the CAPA record, never reconstructed from memory.

## Feeding the result into PFMEA, control plan and audit checklist
When the 8D closes, update the PFMEA with the failure mode, cause, current controls, occurrence, detection and reaction plan.

Update the control plan with the new parameter, inspection method, frequency and reaction plan. Add or revise auditor checklist questions so the next audit verifies the new control.

Use change control to approve the revision, train the affected personnel, and record the effective date.

## Key takeaways
Separate corrective from preventive action, because the complaint and the risk are different populations.
Size containment to the risk and prove it by count, since an unverified containment is a hope.
Define the effectiveness metric before the fix, because a target chosen afterwards always looks met.

## Common mistakes
Closing an 8D when the action is implemented :: Verify the metric first, since implementation is not an effect.
Adjusting a parameter without change control :: Record the change, because an undocumented setting cannot be restored after a shift change.
Updating the 8D but not the control plan :: Revise the control plan and audit checklist, because the fix lives in the documents the line follows.

## Glossary
CAPA :: Corrective and preventive action, the quality-system record behind the 8D.
PFMEA :: Process failure mode and effects analysis, the risk document the 8D updates.
Effectiveness metric :: The measurable rate used to prove that a corrective action worked.
Change control :: The approval route for a documented change to a process or specification.
