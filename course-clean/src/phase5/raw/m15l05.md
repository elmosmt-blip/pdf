## Frame the ECN or DCR as a controlled problem statement
An ECN or DCR starts with a measurable problem, not a preference.

State the affected assembly, part numbers, revision, production quantity and the process step where the defect appears, plus the current controlled documents: drawing revision, land pattern per IPC-7351, stencil thickness, paste type, feeder map, AOI program and reflow profile per IPC-7530.

If the change is only a temporary containment, label it as one, so nobody files it as a design improvement. Use IPC-7711/7721 for rework and repair limits only when discussing repairability, not as a substitute for design change data.

## Quantify the current design first
Use at least 30 consecutive production days or 1000 boards, whichever gives a stable sample, and check the sample size against your MES capability.

Report boards started, boards passed, rework events, scrap, test escapes, cycle time and downtime. Separate common-cause variation from special-cause events.

For defect classification, use the acceptability class the contract requires under IPC-A-610, and record whether defects were confirmed or only called.

## Anticipate design objections with evidence
The usual objections are that the change affects electrical performance, lacks test coverage, increases cost, delays schedule, or adds thermal or mechanical risk.

Answer each with data: joint geometry from cross-section or X-ray, thermal profile margin from thermocouple data, mechanical clearance, and a test coverage map.

Where reliability is questioned, state the qualification status and the residual risk if the change is not made.

## Keep version control explicit
The ECN or DCR lists every document that changes and every document that stays the same: gerber revision, BOM revision, stencil file revision, paste lot or type, feeder map, AOI program, reflow profile and work instruction.

Assign a unique change ID, an effective date, and the affected serial or lot range. Mark superseded revisions obsolete in the PLM or document control system, and stop mixed revisions running on the line at the same time.

## Build an evidence pack a design engineer can audit
The pack holds the baseline data, the defect Pareto, representative photos, SPI and AOI results, X-ray or cross-section images, reflow thermocouple traces, rework and scrap records, cost of poor quality, risk matrix, proposed change, verification plan and rollback plan.

Use SI units and state the measurement uncertainty where it affects the decision. For paste and stencil values, cite the paste and equipment datasheet rather than a remembered figure.

## Negotiate options and residual risk
Present three options: no change, interim containment, and full design change.

For each, state the expected defect rate, rework time, scrap, schedule impact and residual risk. If the design team resists a land-pattern change, offer a process-only trial first — stencil aperture adjustment, paste type change, or placement pressure change — and record the limits of that trial.

Avoid absolute claims. State conditions, sample sizes and the data behind the projection.

## Close the change with post-change data
After implementation, run a pilot and then a production confirmation.

Compare SPI, AOI, X-ray, functional test, rework, scrap, cycle time and downtime against the baseline. Close the ECN or DCR only when the acceptance criteria are met, the controlled documents are updated and the line runs the new revision.

If the post-change data miss the criteria, reopen the change and identify whether the cause is design, process or execution.

## Key takeaways
Baseline the problem on a stated sample, because thirty days of data settles objections that opinion cannot.
Close on post-change data, since approval is not the same as effect.
Offer a process-only trial where design resists, because a bounded experiment is easier to approve than a redesign.

## Common mistakes
Filing a temporary containment as a permanent change :: Label the duration, because a containment recorded as a fix never gets replaced.
Comparing the pilot against a different product mix :: Use the same conditions, since mix moves the defect rate.
Leaving two revisions on the line :: Obsolete the old documents, because mixed revisions make every result ambiguous.

## Glossary
Pilot build :: A limited production run used to confirm a change before release.
Rollback plan :: The documented route back to the previous revision if a change fails.
Test coverage map :: The record of which defects each inspection and test step can detect.
Document control :: The system that holds current revisions and marks superseded ones obsolete.
