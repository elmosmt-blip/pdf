## What AOI metrics measure
AOI metrics are process indicators built from audit data, not direct measurements of the true defect population. AOI screens, so its reported rejects, passes and escapes depend on program setup, optics, lighting, the component library, panel design, paste, reflow and operator verification.

Stratify the metrics by product, line, shift, program version and defect type before using them for a decision. They are most useful compared over time within one product family, and paired with downstream test, rework and field data. A metric that looks good at the AOI station is incomplete when downstream steps mask defects or nobody audits verification.

Review escape rate, false-call rate, verification coverage and first-pass yield as a set rather than as isolated station scores.

## Escape rate
Escape rate is usually defects found after AOI divided by the units, panels or component opportunities inspected. Match the denominator to the question: board-level escapes use boards, joint-level use joints, component-level use components.

Downstream sources include in-circuit test, functional test, manual visual audit, X-ray, rework and field returns. Its limits are the detection capability of those steps, escapes below AOI resolution, intermittent defects, and the time lag before field returns appear.

A low escape rate can mean good detection, downstream masking, or weak downstream detection. Where the downstream audit is weak the rate understates the problem, and where the denominator is too broad a few escapes look insignificant while one component or panel location is failing.

## False-call rate
False-call rate is verified good rejects divided by verified AOI rejects. It needs a verification workflow that dispositions every reject as true defect, false call, marginal or other.

Incomplete coverage turns the rate into an estimate from the verified subset, reliable only when that subset represents all rejects. Operator bias, marginal acceptance, duplicate rejects, program changes and differences between the AOI image and the physical board all bend it.

A false call is not automatically waste: some flag marginal conditions that later escape. It can also show that the program is too sensitive for the current paste, stencil or placement process. Keep the disposition categories stable, because redefining them moves the rate without any process change.

## First-pass yield
First-pass yield is units completed without rework or repair divided by units started.

In the AOI context, separate AOI pass yield, which penalises every AOI reject including false calls, from line first-pass yield, which depends on the final disposition after verification and downstream test. FPY misleads when rework loops, duplicate boards, batch holds or late dispositions are counted inconsistently.

A high FPY with poor verification coverage may hide escapes, and a lower FPY with strong verification may simply reflect better detection. Pair FPY with escape and false-call rates to see whether yield improved because defects were prevented or because detection was relaxed, and keep definitions identical across shifts and products.

## Verification workflow and coverage
A practical workflow runs from the AOI reject to a review of the image and the physical board to a disposition against documented visual acceptance criteria.

Verification coverage is verified rejects divided by total AOI rejects, and it should include random samples of passes, because pass audits estimate the escapes downstream may not catch. Coverage weakens when only high-risk rejects are verified, when operators verify only obvious defects, or when the AOI image is accepted without physical confirmation.

Report coverage beside the false-call rate so the estimate can be read, and add disagreement audits where a second inspector reviews a sample of dispositions, plus clear rules for marginal cases. Otherwise coverage can be high in count and poor in quality.

## Statistical limits and stratification
All three metrics are proportions, so small denominators give unstable results: a few defects in a small audit move the rate substantially.

Control charts, confidence intervals and Pareto analysis by defect type, component, package, panel location, shift and program version say more than a single weekly number. Compare similar products run on similar programs.

Set practice-based thresholds from historical capability, customer requirements and equipment datasheets, and check them against your paste and equipment datasheet. Review them whenever product mix, AOI program, stencil, paste or reflow profile changes, because a target that holds for one family may be wrong for another whose density, packages and panel design differ.

## Using the metrics for improvement
False-call reduction usually starts with program tuning, lighting, fiducial quality, panel layout, component library accuracy and thresholds.

Escape reduction may need better AOI coverage, added X-ray or functional test, and correction of paste, stencil, placement or reflow variation. Coverage improves with training, clear acceptance criteria, disagreement audits and sampled passes.

Let the metrics drive containment and prevention rather than reporting. On THT, AOI sees pin joints poorly, so read escape metrics with X-ray, functional test or manual audit data. Track improvement with before-and-after data on the same denominators and verification rules, so the team can tell whether detection improved, false calls fell, or the problem simply moved to another station.

## Key takeaways
Report escape rate, false-call rate and coverage together, because any one of them alone can be improved by worsening another.
Match the denominator to the level you are judging, since board, joint and component escapes answer different questions.
Keep definitions and stratification fixed across comparisons, or a program revision looks like a process improvement.

## Common mistakes
Reading a falling escape rate as better AOI :: Check downstream detection and audit coverage, because masking produces the same curve.
Quoting a false-call rate from partial verification :: State the coverage, or the number describes only the rejects someone verified.
Comparing rates across products with different densities :: Stratify by product family, since component density changes the detection challenge.

## Glossary
First-pass yield :: Units completed without rework divided by units started.
Verification coverage :: Verified rejects divided by total AOI rejects, showing how much of the data was actually reviewed.
Disagreement audit :: A second review of a sample of dispositions to test consistency.
Stratification :: Splitting a metric by product, line, shift or defect type so the population is comparable.
